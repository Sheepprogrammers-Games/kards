# 回响时间轨 机制规格

本文档定义战斗核心机制「回响时间轨」的完整规则。所有条目均以可直接实现为纯函数 reducer 的粒度书写，
不含待定项。数值常量集中于第 10 节，平衡表落地于 `assets/data/`。

---

## 1. 术语与数据模型

### 1.1 轨道结构

时间轨由 4 个格位组成，索引 `slot ∈ {1,2,3,4}`，UI 标记为 T+1 / T+2 / T+3 / T+4。
轨道分为两条独立泳道（lane），共享同一组格位索引与同一次推进：

- `PLAYER` 泳道：容纳玩家打出的织牌条目，产生回响
- `ENEMY` 泳道：容纳敌方意图条目，不产生回响，在离开 T+4 时结算

每条泳道的每个格位最多容纳 1 个条目。

### 1.2 格位语义

格位索引统一表示「条目在传送带上的位置」，两条泳道的运动方向一致：条目每次推进从
低索引移向高索引，越过 T+4 后离场。语义差异只体现在离场行为上：

- 玩家条目：格位索引 = 回响年龄，索引越高强度系数越低，越过 T+4 进入弃牌堆
- 敌方意图：格位索引 = 引信长度的倒数，越过 T+4 时立即结算伤害

因此「把敌方意图推后」在实现上是把它向低索引方向移动（rewind），「提前引爆」是把它
直接强制结算。两者在同一套位移原语上表达。

### 1.3 数据结构

```
TrackEntry {
  cardId:        string          // 来源卡定义 id
  owner:         PLAYER | ENEMY  // 结算归属方
  effects:       Effect[]        // 卡面效果原子列表
  echoBudget:    int             // 剩余可结算次数，初始 ECHO_BUDGET_DEFAULT
  resolvedHere:  bool            // 在当前格位是否已结算过
  rewindCount:   int             // 已被向低索引移动的次数
  delayCount:    int             // 仅敌方意图：已被延后的次数
  copyDepth:     int             // 0 为原件，1 为副本，副本不可再被复制
  anchored:      bool            // 抗推挤标记
  stolen:        bool            // 由敌轨窃取而来
  snapshot:      CasterSnapshot  // 插入时冻结的施法方修正
}

CasterSnapshot {
  strength:      int
  weakened:      bool
  damageScale:   float           // 遗物与增益的乘算合并结果
  statusPotency: int             // 状态施加量的加算修正
}

Effect {
  kind:          string          // damage / block / applyStatus / draw / gainEnergy / manipulate ...
  amount:        int
  scaleMode:     SCALAR | COUNT | ONCE | THRESHOLD
  scaleTarget:   "amount" | "hits"
  threshold:     float           // 仅 THRESHOLD 使用，见 5.1
}
```

`scaleMode` 决定该效果原子在回响中的行为，是防止数值失控的核心开关：

| scaleMode | 行为 | 适用效果 |
|---|---|---|
| `SCALAR` | 数值乘以格位系数后向下取整 | 伤害、护甲、状态层数 |
| `COUNT` | 攻击次数乘以系数取整，单次数值不变 | 多段攻击 |
| `ONCE` | 仅在打出时结算一次，回响中完全不触发 | 抽牌、获得能量、生成卡、轨道位移 |
| `THRESHOLD` | 当前格位系数 ≥ threshold 时按 100% 触发，否则不触发 | 条件性强效果 |

规则：任何产生**能量、抽牌、卡牌生成、轨道位移**的效果原子必须标记为 `ONCE`。
这是硬性数据约束，由内容加载时的校验器强制执行，违反则构建失败。

## 2. 回合时序

以下为完整的一个回合，编号步骤即 reducer 的执行顺序。同一编号内的操作不可重排。

### 2.1 玩家回合开始

```
1.  turn += 1
2.  player.block = 0                            // 未标记 retain 的护甲清零
3.  tickStatusStartOfTurn(PLAYER)               // 中毒、灼烧、再生结算
4.  settleDeaths()                              // 若战斗结束则返回
5.  resolveEchoes(PLAYER_LANE)                  // 见 2.2
6.  settleDeaths()
7.  energy = energyPerTurn + energyModifier
8.  draw(handSize - hand.length)
9.  resetTurnFlags()                            // igniteCountThisTurn = 0, weavePlays = 0
```

护甲清零（步骤 2）早于回响结算（步骤 5），因此回响产生的护甲在本回合可用。
中毒结算（步骤 3）早于回响结算，因此本回合回响施加的中毒在下回合才生效。

### 2.2 回响结算

```
function resolveEchoes(lane):
  for slot in 1..4 ascending:                   // 严格升序，结果与顺序相关
    e = track[lane][slot]
    if e == null: continue
    if lane == ENEMY_LANE: continue             // 敌轨不回响
    if e.echoBudget <= 0:
      eject(lane, slot, DISCARD); continue
    coef = effectiveCoef(slot)
    applyEffects(e, coef, e.snapshot)
    e.echoBudget -= 1
    e.resolvedHere = true
    if e.echoBudget == 0 or isNullAt(e, coefOf(slot + 1)):
      eject(lane, slot, DISCARD)
```

`isNullAt` 判定条目在下一格位的所有 `SCALAR` / `COUNT` 效果是否全部向下取整为 0。
全为 0 的条目立即退场，避免无价值条目长期占据格位。

结算过程中若目标死亡，条目改为攻击场上最靠前的存活敌人；无存活敌人时该条目按空操作
处理，但仍消耗 `echoBudget`。战斗结束判定只在 `settleDeaths()` 边界发生，不在结算链中途中断。

### 2.3 玩家行动阶段

玩家可任意次数执行 `playCard`，直到能量不足或主动结束回合。

```
function playCard(cardId, target):
  c = hand[cardId]
  cost = c.cost + (c.type == IGNITE ? igniteCountThisTurn : 0)
  assert energy >= cost
  assert isPlayable(c)                          // 引牌要求轨上条目数 >= IGNITE_MIN_ENTRIES
  energy -= cost
  hand.remove(cardId)

  switch c.type:
    WEAVE:
      pushLane(PLAYER_LANE)                     // 见 2.4
      e = makeEntry(c, snapshotOf(player))
      track[PLAYER][1] = e
      applyEffects(e, COEF[1], e.snapshot)      // 打出结算即 T+1 的 100% 结算
      e.echoBudget -= 1
      e.resolvedHere = true
      weavePlays += 1
    IGNITE:
      detonate(c.params)                        // 见 2.5
      discard.push(c)
      igniteCountThisTurn += 1
    DISRUPT:
      applyManipulation(c.params, target)       // 见 2.6
      discard.push(c)

  settleDeaths()
```

关键规则：**打出一张织牌时的结算，就是它在 T+1 格位的 100% 结算**。
原始设定中「打出后进入 T+1，下回合起按系数回响」会导致 T+1 的 100% 系数永远无法被触发
（条目在回合末推进后，下回合开始时已位于 T+2）。统一为「打出即 T+1 结算」后，
系数表的四项全部有效，`resolveSlot(entry, slot)` 成为唯一结算入口，reducer 无分支特例。

引牌与扰牌**不进入时间轨**，结算后直接进入弃牌堆。这使三类牌的资源占用彻底区分：
织牌消耗轨位，引牌与扰牌只消耗能量与手牌。同时它从结构上消除了「扰牌自身回响导致
位移循环」和「引牌自身回响导致引爆循环」两类退化打法。

### 2.4 插入推挤

```
function pushLane(lane):
  if track[lane][4] != null and not track[lane][4].anchored:
    eject(lane, 4, BURN)                        // 溢出退场：移出战斗，不入弃牌堆
  for slot in 3..1 descending:
    e = track[lane][slot]
    if e == null: continue
    dst = nextFreeSlotRightOf(lane, slot)       // 跳过 anchored 条目
    if dst == null:
      eject(lane, slot, BURN)
    else:
      track[lane][dst] = e
      track[lane][slot] = null
      e.resolvedHere = false
```

**溢出退场（BURN）与自然退场（DISCARD）区分对待**：被后续打出的牌挤出 T+4 的条目
移出本场战斗，不进入弃牌堆；由回合末推进自然移出 T+4 的条目进入弃牌堆。

这条规则是整个系统的节流阀。没有它，单回合倾泻手牌只损失最旧条目的 25% 尾部收益，
惩罚过轻，「每回合打光手牌」成为无脑最优解。加入烧毁后，高速倾泻会实际销毁牌组，
使爆发成为需要计价的选择。副作用是玩家可以主动烧掉诅咒牌与起手废牌，这是可接受的
正向涌现。

### 2.5 引爆

```
function detonate(params):
  entries = selectEntries(PLAYER_LANE, params.filter)
  assert entries.length >= IGNITE_MIN_ENTRIES
  for e in entries ascending by slot:
    remaining = sum(COEF[k] for k in (e.slot + 1)..4)
    if not e.resolvedHere: remaining += COEF[e.slot]
    payload = remaining * IGNITE_EFFICIENCY * igniteEfficiencyMod
    payload = min(payload, e.echoBudget * COEF[1] * IGNITE_EFFICIENCY)
    applyEffects(e, payload, e.snapshot)
    e.echoBudget = 0
    eject(PLAYER_LANE, e.slot, DISCARD)
```

引爆按条目**尚未结算的剩余系数之和**计算，再乘以效率系数 `IGNITE_EFFICIENCY = 0.60`。

原始设定的「一次性结算总和」若按 100% 效率实现，则「打出织牌、立即引爆」的收益等于
该牌的全生涯收益且无需等待，时间轨沦为无意义的中间层。乘以 0.60 后：
即打即爆收益 = 100% + 0.6 × 140% = 184%，低于每回合稳定打 1 张的 195%。引爆因此定位为
「以效率换节奏」的清算工具，而非价值引擎。

`igniteEfficiencyMod` 的乘算结果**硬性上限 1.0**。任何遗物都不得使其超过 1.0，
否则等待将被严格支配，机制整体坍缩。

### 2.6 位移原语

所有扰牌效果由以下原语组合而成，原语本身在 reducer 中实现，卡面只声明参数：

| 原语 | 语义 | 约束 |
|---|---|---|
| `push(lane, slot, n)` | 向高索引移动 n 格 | 目标格被占用时连同后方条目一起顺推；被顶出 T+4 的玩家条目按 BURN 处理，敌方意图立即结算 |
| `rewind(lane, slot, n)` | 向低索引移动 n 格 | 目标格被占用时连同前方条目一起顺移，链上每个条目各消耗一次额度；玩家泳道要求 `rewindCount < REWIND_LIMIT`，敌方泳道要求 `delayCount < INTENT_DELAY_LIMIT`，任一环节受限则整体不动 |
| `swap(a, b)` | 交换两个格位的条目，可跨泳道 | 跨泳道交换同时改写 `owner` 并置 `stolen` |
| `copy(lane, slot, dst)` | 复制条目到空格位 | 要求 `copyDepth == 0`；副本 `copyDepth = 1`、`echoBudget = 1`、不可再被复制 |
| `steal(slot)` | 敌轨条目移入玩家泳道同格位 | 要求目标非 `unstealable`；置 `stolen = true`、`echoBudget = 1` |
| `freeze(lane, slot)` | 本回合末不推进 | 消耗该条目 1 点 `echoBudget` 作为代价 |
| `rerecord(slot)` | 用当前施法方状态刷新 `snapshot` | 不改变 `echoBudget` |
| `sustain(slot, n)` | `echoBudget += n` | 上限 `ECHO_BUDGET_MAX` |
| `evict(lane, slot)` | 立即退场并按剩余系数 30% 结算 | 结算后按 DISCARD 退场 |

`rewind` 成功后置 `resolvedHere = false`，条目可在新格位重新结算一次，但受
`echoBudget` 总量约束。

### 2.7 玩家回合结束与敌方阶段

```
10. discardHand()                               // 保留 retain 标记的牌
11. tickStatusEndOfTurn(PLAYER)
12. advanceTrack()                              // 见 2.8，双泳道同时推进
13. settleDeaths()
14. scheduleIntents()                           // 见第 6 节
15. decayStatusStacks()                         // 易伤、虚弱等层数 -1
16. → 回到步骤 1
```

敌人在自己的阶段**不直接发动攻击**，只调度意图。所有敌方伤害都在步骤 12 的推进中落地。
这条统一规则使玩家的每一次干预都作用在同一个时点上，也让「推后」「窃取」「抢拍」
三类操作有确定的结算窗口。

意图在步骤 14 调度、步骤 12 结算，因此一个调度在 T+4 的意图会在下一回合的步骤 12 落地，
玩家拥有完整的一个回合观察并应对，与常规卡牌 Roguelike 的一回合预告等价。

### 2.8 推进

```
function advanceTrack():
  for lane in [PLAYER, ENEMY]:
    for slot in 4..1 descending:
      e = track[lane][slot]
      if e == null: continue
      if e.frozenThisTurn: e.frozenThisTurn = false; continue
      if slot == 4:
        if lane == PLAYER: eject(lane, 4, DISCARD)
        else: resolveIntent(e); track[lane][4] = null
      else:
        track[lane][slot + 1] = e
        track[lane][slot] = null
        e.resolvedHere = false
```

降序遍历保证目标格位在写入前已被腾空。推进不检查 `anchored`：锚定只抵抗插入推挤，
不抵抗回合末推进，因此任何条目都无法永久驻留。

## 3. 资源关系

### 3.1 能量的定位

**能量不再是主资源。** 主资源是轨位回合数（slot-turn）。

理由：能量约束的是「本回合能做多少」，而回响机制的价值分布在多个回合上。若继续以能量
为唯一节流器，一张牌的生涯价值达到面值的 2.4 倍而成本不变，卡面数值必须整体压缩 60%，
同时能量增益类遗物的收益会被回响放大同样的倍数，曲线在中后期必然爆炸。

新的三层资源结构：

| 资源 | 约束对象 | 主要来源 | 主要消耗 |
|---|---|---|---|
| 能量 | 单回合爆发上限 | 每回合重置为 3 | 打出任意牌 |
| 轨位回合数 | 跨回合总吞吐 | 每回合 4 格 × 1 次回响 | 打出织牌（挤压既有条目） |
| 牌组存量 | 战斗总长度 | 抽牌堆 + 弃牌堆 | 自然弃置与溢出烧毁 |

### 3.2 防止能量曲线爆炸的四条措施

1. **能量与抽牌效果不可回响。** `gainEnergy`、`draw`、`createCard` 强制标记 `ONCE`。
   这切断了「回响放大资源产出 → 更多打牌 → 更多回响」的正反馈环。
2. **打牌具有边际成本。** 每打出一张织牌都会推挤既有条目，直接削减已投入条目的剩余
   回响次数。玩家状态越好，多打一张牌的机会成本越高，形成自然的负反馈。
3. **溢出烧毁。** 高速倾泻牌组不只损失回响，还永久损失卡牌，把「能量过剩」转化为
   「牌组耗尽」这一另一个失败维度。
4. **系数总和封顶。** 所有修改系数表的遗物在结算前统一归一化，见第 4.3 节。

### 3.3 吞吐量测算

设玩家每回合打出 `p` 张织牌，稳态下轨道每回合推进 `p + 1` 格（p 次插入推挤 + 1 次回合末推进）。
下表为每张织牌的生涯结算系数总和，以及每回合的总输出系数：

| p | 单卡生涯系数 | 每回合总输出系数 | 每回合消耗手牌 |
|---|---|---|---|
| 0 | 视轨道存量衰减 | 由存量决定，逐回合递减 | 0 |
| 1 | 1.00 + 0.70 + 0.25 = 1.95 | 1.95 | 1 |
| 2 | 平均约 1.57 | 2.15 | 2 |
| 3 | 平均约 1.47 | 4.40（含首回合填轨） | 3 |
| 4 | 平均约 1.35 | 5.40（含首回合填轨） | 4，且每回合烧毁 1 张 |

结论：单卡效率在 `p = 1` 时最高，总输出随 `p` 单调上升但伴随牌组损耗与烧毁。这正是
预期的张力结构——克制换效率，倾泻换节奏。卡面数值按「生涯系数 1.95」为基准线定价，
即同类游戏中一张 9 点伤害的牌在本作印为 5 点。

### 3.4 手牌与抽牌

轨上条目既不在抽牌堆也不在弃牌堆。满轨时牌组循环池减少 4 张，小牌组（12 张起手）下
这是明显的洗牌加速。规则：

- 抽牌堆为空时洗入弃牌堆；两者皆空时按可抽数量抽取，不触发疲劳伤害
- 轨上条目不参与洗牌，引爆退场后回到弃牌堆并可再次进入循环
- 溢出烧毁的条目移出本场战斗，战斗结束后回归常规牌组

## 4. 衰减系数

### 4.1 选定方案

`COEF = [1.00, 0.70, 0.45, 0.25]`，总和 2.40。取整规则统一为向下取整（floor）。

相邻比值为 0.70 / 0.643 / 0.556，是**加速衰减**，非等比。

### 4.2 备选方案对比

| 方案 | 系数 | 总和 | 判定 |
|---|---|---|---|
| 等比 r=0.7 | 1.00 / 0.70 / 0.49 / 0.34 | 2.53 | 尾部过厚。T+4 仍有 1/3 强度，长期持有的机会成本过低，玩家倾向于不打牌以维持满轨，回合节奏停滞 |
| 线性 | 1.00 / 0.75 / 0.50 / 0.25 | 2.50 | 差值恒定，四个格位没有质变点，引爆时机缺乏明确判据，扰牌的位移收益线性且乏味 |
| 阶梯 | 1.00 / 0.50 / 0.50 / 0.25 | 2.25 | 心算最容易，但 T+2 与 T+3 完全等价，实际把 4 格轨压缩为 3 段，扰牌设计空间损失约四分之一 |
| **加速衰减（选定）** | 1.00 / 0.70 / 0.45 / 0.25 | 2.40 | 见下 |

选定方案的三条依据：

1. **小整数友好。** 对常见面值向下取整后得到清晰序列：
   `6 → 6/4/2/1`，`8 → 8/5/3/2`，`10 → 10/7/4/2`，`5 → 5/3/2/1`，`3 → 3/2/1/0`。
   玩家无需计算即可读出每格数值，且低面值牌在尾部自然归零并触发自动退场，
   低价值条目不会长期占位。
2. **衰减加速使引爆时机有唯一解。** T+1→T+2 损失 30%，T+3→T+4 损失 44%。
   持有越久边际损失越大，玩家有明确的「该清算了」的信号点，而非无限拖延。
3. **总和 2.40 是可用的定价基线。** 全部卡面数值以 `面值 × 1.95`（稳态）为战力口径，
   `2.40` 为理论上限，两者的差值即为轨道管理技巧的表现空间。

### 4.3 反向增幅遗物的失控封堵

「反向增幅」类遗物（回响随格位增强而非衰减）若实现为对系数表的乘算加成，会直接放大总和。
例如把表改为 `1.00 / 1.30 / 1.60 / 1.90`，总和 5.80，单卡生涯价值增至 2.4 倍原值，
且配合冻结与锚定可趋近无限。

封堵采取三层：

**第一层：形状可变，总和不可变。** 所有系数修改器只能重塑分布形状，不能改变总量。
反向增幅遗物的正确实现是**倒置系数表**：`[0.25, 0.45, 0.70, 1.00]`，总和仍为 2.40。
它彻底改变最优策略（从速打速清变为长期持有、末端清算），但不改变价值预算。

**第二层：归一化钳制。** 所有遗物修改器应用完毕后，reducer 统一执行：

```
function effectiveCoefTable(state):
  t = applyRelicModifiers(BASE_COEF, state.relics)
  s = sum(t)
  if s > ECHO_SUM_CAP:                          // ECHO_SUM_CAP = 3.20
    t = t.map(x => x * ECHO_SUM_CAP / s)
  return t
```

允许总和在 2.40 与 3.20 之间浮动，为遗物留出真实成长空间，但设置绝对天花板。
归一化是乘算而非截断，保证遗物设计的形状意图不被破坏。

**第三层：条目生涯预算。** 每个条目的 `echoBudget` 初始为 4、上限 6。
无论系数表如何变化、无论被回溯或冻结多少次，单个条目的结算次数有硬上限。
这是对抗所有循环类退化的最终防线，见第 5 节。

## 6. 敌人意图挂轨

### 6.1 意图生成

每个敌人持有 `intentScript`：一个由 `(intentCardId, preferredSlot, weight)` 组成的加权列表。
调度在步骤 14 执行，全部随机取自 state 中的种子 RNG。

```
function scheduleIntents():
  for enemy in enemies (按 enemy.index 升序):
    for k in 1..enemy.intentsPerTurn:
      pick = weightedPick(enemy.intentScript, rng)
      slot = firstFreeSlotFrom(ENEMY_LANE, pick.preferredSlot, direction = descending)
      if slot == null:
        enemy.charge += 1                       // 敌轨已满，意图丢失但转为蓄力
      else:
        track[ENEMY][slot] = makeIntentEntry(pick, enemy)
```

`firstFreeSlotFrom` 从 `preferredSlot` 向低索引方向寻找空位（即引信更长的方向）。
找不到空位时转为 `charge` 层数，每层使该敌人下一个成功挂轨的意图数值 +25%。
这条规则封堵了「用扰牌把敌轨塞满以使 Boss 无法行动」的退化打法。

默认配置：

| 敌人类型 | intentsPerTurn | preferredSlot | 效果 |
|---|---|---|---|
| 杂兵 | 1 | 4 | 一回合预告，与常规卡牌 Roguelike 等价 |
| 精英 | 1 | 4 与 3 交替 | 偶尔出现两回合预告的重击 |
| Boss | 2 | 4 与 2 | 每回合同时挂一个近击与一个远击，玩家必须持续做优先级判断 |

### 6.2 意图的推移与结算

- 意图不回响。它在被推出 T+4 时通过 `resolveIntent` 结算，或被 I8 抢拍强制结算。
- `rewind`（延后）使意图向低索引移动，`delayCount += 1`，上限 `INTENT_DELAY_LIMIT = 2`。
  达到上限的意图无法再被延后，扰牌对其失效并给出明确的不可选反馈。
- `push`（推前）使意图向高索引移动，等于让它更早落地。目标格被占用则操作失败。
- 意图结算时读取**实时**的敌方修正与玩家防御状态，不使用快照。因此在意图落地前给敌人
  叠虚弱、给自己叠护甲都是有效的。
- 意图被延后时不衰减也不增强，数值恒定。延后是纯粹的时间置换，不是伤害减免。

### 6.3 窃取的归属

`steal(slot)` 将意图条目从敌方泳道移入玩家泳道的同一格位，并写入：

```
owner = PLAYER
stolen = true
echoBudget = 1
copyDepth = 1                                   // 被窃取的意图不可再被复制
snapshot = snapshotOf(player)
```

结算规则：

- 被窃取的意图**在玩家泳道正常参与步骤 5 的回响**，结算一次后 `echoBudget` 归零并退场。
  数值再乘 `STOLEN_RATE = 0.50`。
- 目标为场上最靠前的存活敌人；若原持有者仍存活则优先指向原持有者。
- 窃取立即使原敌人 `charge += 1`。窃取是延迟压力，不是免除压力。
- 被窃取的意图占据一个玩家轨位，会推挤既有条目。窃取有真实的机会成本。
- 意图条目可标记 `unstealable`，Boss 的核心大招固定携带该标记，同时携带 `undelayable`。

### 6.4 Boss 的多意图压迫

Boss 每回合调度 2 个意图，长期占据敌轨 3 到 4 个格位，形成以下压迫结构：

1. **格位竞争。** 敌轨满载时玩家的 `swap`、`steal`、`push` 全部因目标格被占而失败率上升，
   干预窗口自然收窄。
2. **优先级强制。** 同时可见 3 个未来伤害时，玩家的扰牌数量不足以全部处理，必须放弃一个。
3. **蓄力惩罚。** 玩家若通过堵塞敌轨规避伤害，敌人累积 `charge`，后续单次伤害成倍增长，
   规避策略被转化为延迟的更大风险。
4. **不可干预锚点。** Boss 的 `unstealable` + `undelayable` 大招固定挂在 T+1，
   给玩家 4 个回合的准备期，但完全不可推移，只能靠护甲与生命硬接。

## 7. 状态效果交互

### 7.1 状态不进入时间轨

状态层数存放在实体上，不存放在轨道条目上。进入时间轨的是「施加状态」这个效果原子，
它按 `SCALAR` 缩放：`applied = floor(base × coef + snapshot.statusPotency × coef)`，
结果为 0 时不触发。

例外：标记 `bindToEntry` 的状态在其来源条目退场时层数归零。用于设计「只在回响期间生效」
的强力减益，为其提供天然的时限而不需额外计时器。

### 7.2 施法方快照与防御方实时读取

这是本节最关键的规则，也是对原始设定的一处修正。

- **施法方修正在条目插入时冻结**，写入 `snapshot`。包括力量、虚弱、伤害倍率遗物、
  状态施加强度。
- **防御方修正在每次结算时实时读取**。包括易伤、护甲、抗性、目标当前生命。

若施法方修正实时读取，则「先铺满 4 张条目，再叠 3 点力量」会使力量作用于全部 4 次回响，
每张牌的力量收益变为 `3 × 2.40 = 7.2` 点，力量类遗物的价值被回响系统整体放大一个数量级，
构筑空间坍缩为「只叠力量」。快照规则把力量的收益锁定在获取时点，与常规卡牌游戏一致。

防御方实时读取则保留了战术价值：给敌人上易伤后，轨上已有条目的后续回响全部受益，
这正是玩家应当追求的操作。

D9「重录」用当前状态刷新快照，是力量流派兑现收益的显式操作，成本是一张牌加能量。

### 7.3 具体状态的结算规则

| 状态 | 结算时点 | 与回响的关系 |
|---|---|---|
| 中毒 | 步骤 3，早于回响 | 本回合回响施加的中毒下回合才扣血。层数按系数向下取整施加 |
| 护甲 | 步骤 2 清零，早于回响 | 回响产生的护甲本回合可用，可抵挡步骤 12 落地的敌方意图 |
| 易伤 | 结算时实时读取，步骤 15 层数 -1 | 本回合施加的易伤对本回合步骤 12 落地的敌方意图生效 |
| 虚弱 | 施法方快照冻结 | 条目插入时的虚弱状态决定其全部回响的削减，后续解除虚弱不影响已在轨条目 |
| 力量 | 施法方快照冻结 | 同上，需 D9 重录才能更新 |
| 灼烧 | 步骤 3 | 与中毒同时点，先中毒后灼烧，顺序固定 |
| 再生 | 步骤 3 之后、步骤 4 之前 | 保证再生可以救回中毒致死 |

### 7.4 取整与死亡判定

- 全部缩放使用向下取整，无最小值保底。设置最小值 1 会使 1 点面值的多段攻击在所有格位
  保持满值，形成小数值农场型退化打法。
- 多段攻击缩放次数而非单次数值（`scaleTarget = "hits"`），避免同一漏洞。
- 死亡判定只在 `settleDeaths()` 边界发生。结算链中途目标死亡时，后续条目重定向到
  最靠前的存活敌人；无存活敌人时按空操作处理并照常消耗 `echoBudget`。

## 8. 退化打法与封堵

### 8.1 回溯循环

**打法**：用扰牌反复把强力条目拉回 T+1，永久享受 100% 结算。

**封堵**：三重。扰牌不进入时间轨故位移本身无法回响；`REWIND_LIMIT = 1` 限制单条目
被回溯的次数；`echoBudget` 上限 4（延音后最高 6）为条目结算次数设置绝对天花板。
理论最大生涯系数 = `6 × 1.00 = 6.00`，需要消耗 1 张织牌 + 1 张回溯 + 2 张延音 + 对应能量，
是可接受的高投入构筑，而非无限循环。

### 8.2 引爆连锁

**打法**：引爆 → 用低费牌重新填轨 → 再次引爆，单回合内多次清算。

**封堵**：引爆后轨道清空，第二次引爆面对的是本回合新填入的条目，其剩余系数已因
`resolvedHere = true` 而扣除了 T+1 部分；`IGNITE_MIN_ENTRIES = 2` 要求轨上至少 2 个条目；
本回合内第 N 次引爆费用 `+ (N - 1)`；`igniteEfficiency` 硬上限 1.0。四者叠加使连锁引爆
在数学上永远劣于一次性引爆满轨。

### 8.3 零风险滚雪球

**打法**：不打牌，只靠满轨回响的护甲与伤害无限拖延。

**封堵**：回合末推进是无条件的，不打牌时轨道仍每回合右移一格，3 回合内必然清空。
低面值条目在尾部取整归零并自动退场。冻结原语的代价是 `echoBudget`，冻结 N 回合就
少结算 N 次，净收益为零。敌方 `charge` 机制使拖延的伤害持续累积。

### 8.4 手牌倾泻

**打法**：每回合打光手牌，最大化每回合总输出。

**封堵**：插入推挤造成的溢出退场按 BURN 处理，卡牌移出本场战斗。`p = 4` 时每回合烧毁
1 张牌，12 张起手的牌组在 8 个回合内耗尽。这不是禁止而是计价——短线速攻是合法策略，
代价是战斗长度上限。

### 8.5 复制分叉

**打法**：复制最强条目填满 4 格，再引爆。

**封堵**：`copyDepth` 字段。副本 `copyDepth = 1`，不可再被复制；副本 `echoBudget = 1`，
只结算一次；副本占用真实格位，会推挤原件。W11 分裂型织牌同样受此约束。
复制的上限是「1 原件 + 3 副本」，且需要 3 张扰牌，收益与投入匹配。

### 8.6 小数值农场

**打法**：使用面值 1 的多段攻击牌，利用取整保底在所有格位维持满值。

**封堵**：向下取整无保底，面值 1 在 T+2 即归零。多段攻击缩放次数而非单次数值。
条目在下一格位全部效果归零时自动退场，不占用格位。

### 8.7 力量追加

**打法**：先铺满时间轨，再集中叠加力量，使全部在轨条目的后续回响获得成倍收益。

**封堵**：施法方修正在条目插入时快照冻结。想让已在轨条目受益必须使用 D9 重录，
每张重录只作用一个条目，成本与收益线性对应。

### 8.8 意图窃取农场

**打法**：持续窃取 Boss 的高数值意图，把敌方伤害转为己方伤害，同时免疫全部攻击。

**封堵**：窃取后 `echoBudget = 1` 且数值 × 0.50，只结算一次；占用玩家轨位并推挤既有条目；
使原敌人 `charge += 1`，下一个意图数值 +25%；Boss 核心意图标记 `unstealable`。
窃取因此定位为「一次性的伤害转移」，不是持续引擎。

### 8.9 敌轨堵塞

**打法**：用 D12 空拍或跨轨换位把敌方泳道全部格位填满，使敌人无法调度新意图。

**封堵**：调度失败时敌人累积 `charge`，每层使下一个成功挂轨的意图 +25%。堵塞越久，
解除堵塞时的伤害越高。同时空拍条目本身占用玩家的手牌与能量，堵塞 4 格需要持续投入。

### 8.10 能量引擎

**打法**：使用产生能量或抽牌的织牌，让回响持续产出资源，形成资源正反馈。

**封堵**：`gainEnergy`、`draw`、`createCard` 强制标记 `ONCE`，回响中完全不触发。
该约束由内容加载校验器在构建期强制执行。I9 连锁引爆的能量返还有本回合上限 2，
且引爆本身会清空轨道。

## 9. 新手认知负荷

前三场战斗按机制分层解锁。锁定通过 `trackLength` 与 `unlockedCardTypes` 两个 state 字段
实现，reducer 无需特例分支。

### 第 1 场：只暴露「牌会重复」

| 项目 | 配置 |
|---|---|
| 轨道长度 | `trackLength = 2`（T+3 / T+4 灰显且不可用） |
| 系数表 | `[1.00, 0.70]` |
| 可用牌型 | 仅织 |
| 敌方意图 | 1 个杂兵，`intentsPerTurn = 1`，`preferredSlot = 2`（等于此时的末格） |
| 玩家可用干预 | 无 |
| 新概念数 | 1 |

玩家需要理解的唯一事实：打出的牌不会消失，下回合会以 70% 强度再触发一次。
两格轨道使这一点在两个回合内即可完整观察到。敌方意图挂在同一条轨上，直观呈现
「敌人的攻击也在这条线上倒计时」，但此时玩家无法干预，只需读取。

### 第 2 场：暴露完整衰减梯度与清算

| 项目 | 配置 |
|---|---|
| 轨道长度 | `trackLength = 4` |
| 系数表 | `[1.00, 0.70, 0.45, 0.25]` |
| 可用牌型 | 织 + 引 |
| 敌方意图 | 1 个杂兵，`preferredSlot = 4` |
| 新概念数 | 2（四格梯度、引爆清算） |

第 3、4 格解锁使玩家看到完整衰减曲线，并第一次面对「等待还是清算」的判断。
本场敌人生命值刻意设定为「不引爆打不掉，引爆刚好击杀」，让引爆的价值在一次战斗内自证。
本场不引入溢出烧毁：牌组配置保证手牌不足以填满 4 格。

### 第 3 场：暴露轨道操纵与敌轨交互

| 项目 | 配置 |
|---|---|
| 轨道长度 | 4 |
| 可用牌型 | 织 + 引 + 扰（仅 D1 右推、D3 延后、D7 窃取三个模板） |
| 敌方意图 | 1 个精英，`intentsPerTurn = 2` |
| 新概念数 | 3（位移、延后、窃取） |

首次出现「两个未来伤害同时可见但只能处理一个」的局面，逼出优先级判断。
窃取在此场以最简形式呈现（单次结算，数值减半），玩家不需要理解 `charge` 机制即可使用，
`charge` 的数值影响在第 4 场首次出现 Boss 时才具备可感知的量级。

溢出烧毁在第 3 场首次可能触发，UI 需在玩家将要挤出 T+4 条目时给出明确的预览标记。

### 未在前三场暴露的内容

反向增幅遗物、冻结、复制、重录、锚定、传导、`bindToEntry` 状态、Boss 多意图结构，
全部推迟到第一层区域后半段。前三场的目标是让玩家能够独立说出三句话：
牌会重复且逐渐变弱；引可以把未来一次性换成现在；扰可以改变东西在轨上的位置。

## 11. 不变量

以下条件在每次 reducer 调用返回后必须成立，逐条对应 `src/engine/__tests__/` 中的用例。

| 编号 | 不变量 |
|---|---|
| I1 | 每条泳道恰有 4 个格位，每格至多 1 个条目 |
| I2 | `0 <= entry.echoBudget <= ECHO_BUDGET_MAX`，仅 `sustain` 可使其增加 |
| I3 | `sum(effectiveCoefTable(state)) <= ECHO_SUM_CAP` |
| I4 | `IGNITE_EFFICIENCY * igniteEfficiencyMod <= IGNITE_EFFICIENCY_CAP` |
| I5 | 单个条目的生涯结算系数总和 `<= echoBudgetInitial * COEF[1]` |
| I6 | 一个回合内轨道推进次数 `== weavePlays + 1 - frozenCount` |
| I7 | 单个条目在一个回合内的结算次数 `<= 2`（回响 1 次 + 引爆 1 次），且引爆后必然退场 |
| I8 | `entry.rewindCount <= REWIND_LIMIT` 且 `intent.delayCount <= INTENT_DELAY_LIMIT` |
| I9 | `entry.copyDepth <= 1`，`copyDepth == 1` 的条目不能作为 `copy` 与 `steal` 的来源 |
| I10 | 任何 `scaleMode == ONCE` 的效果原子在 `resolveEchoes` 中不产生任何状态变更 |
| I11 | 相同种子与相同输入序列产生逐字节相同的状态，reducer 内无 `Date`、`Math.random`、外部 IO |
| I12 | 战斗结束判定只在 `settleDeaths()` 边界发生，结算链中途不提前返回 |

## 12. 对初定规则的修正汇总

| 初定规则 | 修正后 | 失效场景 |
|---|---|---|
| 打出的牌进入 T+1，每回合开始时按格位系数回响 | 打出即为该牌在 T+1 的 100% 结算 | 条目在回合末推进后位于 T+2，T+1 的 100% 系数永远不会被触发，系数表首项为死项 |
| 每格容纳打出的所有牌 | 每格恰好 1 个条目，插入时向高索引推挤 | 格位无容量上限则轨道价值随出牌数线性累积，无负反馈，能量成为唯一约束并在中期爆炸 |
| 移出 T+4 的牌进入弃牌堆 | 自然推进移出者进入弃牌堆；被插入推挤挤出者移出本场战斗 | 两者不区分时，倾泻手牌只损失 25% 尾部收益，惩罚过轻，最优解退化为每回合打光手牌 |
| 引牌一次性结算轨上全部回响的总和 | 结算尚未兑现的剩余系数之和，再乘效率 0.60 | 100% 效率下「打出即引爆」等价于该牌的全生涯收益且无需等待，时间轨沦为无意义的中间层 |
| 扰牌作用于轨上的牌 | 扰牌与引牌均为瞬发，不进入时间轨 | 位移效果若可回响，则「拉回 T+1」在第二回合起自动重复，构成无限价值循环 |
| 敌方意图挂在同一条时间轨上 | 同一轨道分玩家、敌方两条泳道，共享格位索引与推进 | 单泳道混排时插入推挤的归属与顺序无法定义，且玩家牌可被敌方意图挤出，产生不可控的负反馈 |
| 未定义施法方状态的读取时点 | 施法方修正插入时快照冻结，防御方修正结算时实时读取 | 实时读取时「铺满轨道后叠力量」使力量收益乘以 2.40，构筑空间坍缩为单一流派 |
| 未定义条目结算次数上限 | `echoBudget` 初始 4、上限 6 | 缺少生涯预算时，任意回溯、冻结、复制效果的组合都能构成无限循环 |
| 反向增幅遗物直接放大系数 | 只允许重塑系数分布形状，总和经归一化钳制于 `ECHO_SUM_CAP` | 直接放大时总和可达 5.80，单卡价值增至 2.4 倍并与冻结、锚定叠乘趋近无限 |
